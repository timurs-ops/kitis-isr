# tools — автопроверка ДЗ

`checker.js` — движок, `checker.css` — оформление. В папке каждого шага лежат `check.html` (страница проверки)
и `checks.js` (список проверок именно этого шага).

## Как это работает

1. Вы открываете **корень репозитория** в VS Code → Go Live (Live Server).
2. Открываете `steps/step-XX-.../check.html` по `http://127.0.0.1:5500/...`.
3. Движок загружает ваш `index.html` в iframe (тот же источник — значит, можно читать DOM, стили, localStorage и кликать).
4. Проверки выполняются по очереди, результат — список ✓/✗ с подсказками и счёт «N / M».

Через `file://` проверка не работает (браузер запрещает читать чужие файлы) — движок это ловит и объясняет.

## Контракт проверок

```js
runChecks({
  page: 'index.html',      // что грузить в iframe
  query: '',               // необязательный ?query для первой загрузки
  checks: [
    { title: 'Что проверяем', hint: 'Подсказка при провале',
      test: async (ctx) => true /* или false, или throw */ },
  ]
});
```

Возможности `ctx`: `doc`/`win` (iframe), `exists/all/text/rect/css/cssOf`, `click/type/submit` (шлют настоящие события),
`width(px)` (проверка адаптива), `reload(query)` (перезагрузка iframe, например с `?now=`), `ls` (localStorage iframe),
`until(fn, ms)` (подождать асинхронный результат), `sleep(ms)`.

## Принципы

- Проверяется именно **контракт задания** (классы, id, функции), а не «красота». Красоту смотрим визуально отдельно на защите (если это требуется).
- Проверки детерминированы: данные фиксированы (`data/`), время фиксировано (`?now=`), localStorage чистится перед тестами.
- Зелёный чекер ≠ зачёт: зачёт = чекер + ручные критерии + защита (см. docs/GRADING.md).
- Вам можно (и нужно, на полном треке, далеко не сразу) предлагать писать свои проверки — это отдельный критерий понимания происходящего.
