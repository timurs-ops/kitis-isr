# Как сдавать ДЗ и что такое «зачёт»

Все правила — здесь. Сюрпризов на приёмке постараюсь не устраивать :о).

## Твой репозиторий

Один репозиторий на весь курс (создан из шаблона на [старте](STUDENT-START.md)).
Папки `steps/step-XX-...` — твои работы. Корневой `index.html` — витрина «Мои работы».
GitHub Pages показывает всё сразу: я открываю одну ссылку и вижу весь твой прогресс.

## Ритм сдачи

- **Дедлайн недели: воскресенье 23:59.**
- Сдача шага = три вещи:
  1. работа закоммичена и видна на Pages;
  2. в папке шага заполнен `REVIEW.md` (шаблон — [templates/REVIEW.md](../templates/REVIEW.md));
  3. в папке шага заполнен `SUBMISSION.md` (шаблон — [templates/SUBMISSION.md](../templates/SUBMISSION.md));
  4. автопроверка `check.html` прогнана (число N/M честно указано в отчёте).

## Зачёт шага — 10 баллов

| Часть | Баллы | Кто проверяет                                    |
|---|---|--------------------------------------------------|
| Автопроверка (`check.html`) | 4 | машина, пропорционально: 13/13 → 4, 10/13 → 3, … |
| Ручные критерии (раздел «Зачёт» в README шага) | 4 | я / ревьюер                                      |
| Защита | 2 | я                                                |

Шаги без автопроверки (00, 08, 09, 10): ручные критерии 8 + защита 2.

**Зачёт = ≥7 баллов И защита пройдена.** Зелёный чекер без защиты — не зачёт.

## Примерная защита (5–10 минут)

1. Два вопроса по твоему коду: «почему здесь flex?», «что будет, если `room === null`?», «зачем `preventDefault`?».
2. Живая правка при мне: «поменяй цвет полоски», «добавь ещё одно поле», «сделай воскресенье рабочим днём».

Не можешь объяснить строку — шаг не сдан, даже если чекер зелёный. Это не наказание, это тренировка:
на ДЭ будет ровно так же, только строже.

## Статусы и пересдачи

`✅ зачёт` · `🔁 на доработке` · `❌ не сдано` · `· не начинал`

- Пересдачи — **без ограничений**, пока не зачёт.
- Сдал после дедлайна — максимум **8/10** за шаг (опоздание видно в таблице).
- «На доработке» — конкретный список правок в комментарии, не «переделай всё».

## Парное ревью

Каждую неделю ты проверяешь работу **одного** одногруппника по ротации (список согласуем),
по чек-листу [templates/REVIEW.md](../templates/REVIEW.md). Качественное ревью (нашёл реальный баг /
задал вопрос по коду) — **+1 бонусный балл**. Ревью — это тоже навык ДЭ: экспертов учат смотреть чужой код.

## Бонусы

| За что                                                         | Сколько |
|----------------------------------------------------------------|---|
| Качественное парное ревью                                      | +1 / неделя |
| Менторство (помощь на лабах, в чате, доп. проверки для чекера) | +2 / месяц |
| Принятый PR в любой проект на GitHub по теме                   | +5 |

## Списывание и ИИ

ИИ пользоваться **можно** — правила в [AI-POLICY.md](AI-POLICY.md). Чужой код без понимания = не сдано
+ личная пересдача. Выдать чужую работу за свою — то же самое. Защита всё покажет, не трать ничье время впустую.

## Таблица группы

Статусы публичны таблицу закрепим в чате — видно, кто где.
Итоговые баллы сообщаю лично. Публичная таблица — не для того, чтобы меряться баллами, а для темпа:
отставание видно сразу, и помощь приходит раньше.
