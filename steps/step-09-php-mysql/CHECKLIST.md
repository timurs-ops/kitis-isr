# Шаг 09 · ручная приёмка (ручные 8 + защита 2)

## Смоук-сценарий (пройди сам, потом покажи преподавателю)

1. `schema.sql` импортирована, таблицы `users` и `bookings` видны в phpMyAdmin.
2. Регистрация с валидными данными → запись в `users`; в поле `password_hash` — **хеш**, не пароль.
3. Регистрация с невалидными данными (латинское ФИО, короткий пароль, занятый email) → ошибки под полями, записи нет.
4. Вход верный → кабинет; неверный пароль и несуществующий email → **одинаковая** ошибка «Неверный e-mail или пароль».
5. Без входа `index.php` → редирект на login; `admin.php` под студентом → 403.
6. Создал заявку → видна в «моих», статус «новая».
7. `UPDATE users SET role='admin' …` → админка видит **все** заявки с авторами.
8. Подтвердил заявку → статус изменился, студент это видит.
9. Вторая заявка на ту же **аудитория+дата+пара** → при подтверждении конфликт, понятное сообщение, статус не меняется.
10. Отклонил с причиной → причина видна студенту.
11. XSS-проверка: цель заявки `<script>alert(1)</script>` → отображается **текстом**, ничего не выполняется.
12. SQL-инъекция: email `' OR 1=1 --` при входе → ничего не ломает, входа нет.

## Баллы (ручные 8)

По 1 баллу за пункты: **2, 3, 4, 6, 8, 9, 11, 12**. Остальные пункты — допуск к приёмке.

**Lite-версия (экспресс):** пункты 1–6, 11, 12 (без админки и конфликта) → те же 8 баллов пропорционально.

## Защита (2 балла)

- Объясни своими словами: что делает `prepare` + `execute` и почему склейка SQL опасна (покажи на примере).
- Объясни `password_hash` / `password_verify`: почему нельзя хранить пароль открыто и почему хеш нельзя «расшифровать».
- Живая правка: добавь в заявку поле «комментарий» (форма → INSERT → вывод).

## Частые ошибки

- Забыл `session_start()` — он уже в `db.php`, не дублируй.
- `header('Location: …')` после вывода HTML — не работает; редирект делай до разметки.
- Вывод без `e()` — XSS (пункт 11 сразу ловит).
- Пароль в INSERT открыто — пункт 2 сразу ловит.
