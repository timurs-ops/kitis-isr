# Шаг 06 · Регистрация и вход (прототип модуля «безопасность» ДЭ)

**Цель:** формы с валидацией — как на экзамене. Пока это учебный прототип: «база» в localStorage.
На шаге 9 перенесём на PHP+MySQL и узнаем, почему хранить пароли открыто **нельзя**.

## Правила валидации

| Поле | Правило |
|---|---|
| ФИО | кириллица, 2–3 слова через пробел (допускается дефис). «Ivan Petrov» — ошибка |
| Телефон | маска **при вводе**: цифры `9123456789` → `+7(912)-345-67-89` |
| Email | формат `a@b.c` (простая проверка: нет пробелов, есть `@` и точка после неё) |
| Пароль | ≥8 символов, обязательно **и буквы, и цифры** |
| Подтверждение | совпадает с паролем |
| Email | не занят другим пользователем |

- Ошибки — в `span[data-error-for="имяполя"]` (уже в разметке). При **каждой** отправке старые ошибки очищаются.
- Вход: ошибка **всегда одинаковая** — «Неверный e-mail или пароль». Нельзя подсказывать, существует ли email.

Подсказка по регуляркам (разбери их, не копируй слепо — на защите спросят):
```js
var FIO_RE   = /^[А-ЯЁа-яё-]+ [А-ЯЁа-яё-]+( [А-ЯЁа-яё-]+)?$/;
var EMAIL_RE = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
var PASS_RE  = /^(?=.*[A-Za-zА-Яа-яЁё])(?=.*\d).{8,}$/;
```

## Хранилище (учебное!)

- `localStorage['kitis-de:users']` — JSON-массив `{fio, phone, email, password}`;
- `localStorage['kitis-de:session']` — JSON `{email: …}` после успешного входа.

Пароли открыто — **только** потому, что это прототип в браузере владельца. На защите объясни,
почему так нельзя на сервере (мостик к `password_hash` на шаге 9).

## Контракт id (уже в разметке — не переименовывай)

`#reg-form, #fio, #phone, #email, #password, #password2, #reg-success,
#login-form, #login-email, #login-password, #login-error`, ошибки — `[data-error-for="fio"]` и т.д.

Разметка форм готова, помощники в `script.js` тоже — твоя работа: маска, валидация, хранилище.

## Проверка
